# Browser control regression proof — 2026-09-17

The Eidos desk repeatedly reopened its configured work URL after SSO changed the tab URL. Each replacement redirected to Eidos login and stole focus. The live jar reached 671 tabs before work was paused; 658 empty, hidden, single-history duplicates were safely closed.

## Fix

- Persist the assigned target ID across redirects and desk restarts.
- Attempt tab creation once per explicit work start, with no blind retry after an uncertain result.
- Stop when the assigned target closes; repeated Work clicks reuse the worker.
- Take over cancels both workers and waits for any in-flight action before acknowledging. Human control persists across restart, including when autowork is configured.
- Continue performs no navigation, focus, or implicit resume, and cannot prove authentication.
- Cancel login waits promptly. Login workers stay with their target and stop if the user switches tabs.
- Remove internal demo link-clicks and chat messages. Passive gate inspection is read-only; idle desks ask before filling saved credentials.

- Isolated Chromium used the already-installed jar image in a temporary container with an empty profile, no host mounts, no credentials, and loopback CDP. It never drove the user's jar.
- Browser proof: one target through SSO redirects; Continue and repeated Work create zero duplicates; takeover preserves a manually selected tab; human control survives a desk restart with autowork enabled; closing a work target creates zero replacement tabs.
